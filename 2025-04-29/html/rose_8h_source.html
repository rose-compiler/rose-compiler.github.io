163  * Make sure that autoconf macros are not defined in user code. This test is here because CPP symbols defining the presence or
164  * absence of certain features detected by GNU autoconf (or cmake's cmake/ConfigureChecks.cmake) pollute the global name
165  * space. This makes it impossible for a user to include both ROSE's configuration results in conjunction with the
166  * configuration results of any other package.
167  *
168  * If a ROSE public header file truly needs to know a configuration result, then modify scripts/publicConfiguration.pl
169  * to include the name of the symbol you need (e.g., HAVE_PTHREAD_H). Then config.status (which is run as part of the
170  * configuration process) will create a file named "rosePublicConfig.h" with properly scoped CPP symbols (e.g.,
171  * "ROSE_HAVE_PTHREAD_H).
172  *
173  * For legacy code that includes "rose_config.h" followed by "rose.h", simply undefine CONFIG_ROSE between those two
174  * includes. It is safe to do this because CONFIG_ROSE is not used for any other purpose.
175  *
176  * This test is here rather than in src/testRoseLib.C so that developers will get this error sooner rather than having to
177  * wait until all of ROSE is compiled. However, it does mean that developers will need to be a bit more careful about
178  * including both the private (rose_config.h) and public (rosePublicConfig.h) files in tandem.
179  ******************************************************************************************************************************/
