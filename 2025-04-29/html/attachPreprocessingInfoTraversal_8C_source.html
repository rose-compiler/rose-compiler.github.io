3 Remarks on Unparsing and on attaching preprocessing information to AST nodes
4 ----------------------------------------------------------------------------
5 Markus Kowarschik, 10/2002
6 
7 The SgFile (always) constructor calls the function
8 void attachPreprocessingInfo(SgFile *sageFilePtr);
9 which in turn calls getPreprocessorDirectives (see above) and then
10 invokes a tree traversal in order to attach the preprocessor directives
11 (i.e., the preprocessingInfo objects) to located nodes in the AST.
12 (Currently, we only attach preprocessingInfo objects to SgStatement
13 objects.)
14 
15 For this purpose, I added a new data member
16 attachedPreprocessingInfoType* attachedPreprocessingInfoPtr;
17 to the SgLocatedNode class. This is done in ROSETTA/src/node.C.
18 
19 Furthermore, I added the corresponding access functions:
20 void addToAttachedPreprocessingInfo(preprocessingInfo *prepInfoPtr);
21 attachedPreprocessingInfoType* getAttachedPreprocessingInfo(void);
22 to the SgLocatedNode class. This is done in ROSETTA/Grammar/LocatedNode.code.
23 
24 The tree traversal works as follows: whenever it hits a located node
25 (currently: a statement), it checks if there is preprocessing info the
26 line number of which is less or equal than the line number of the current
27 located node (currently: of the current statement). If this is the case,
28 the corresponding preprocessing info is attached to the current
29 located node (currently: before the current statement), unparse flag: "before".
30 All this is done in the evaluateInheritedAttribute member function of the
31 derived tree traversal class.
32 
33 The evaluateSynthesizedAttribute member function deletes the list of
34 preprocessingInfo objects as soon as the traversal returns to a SgFile
35 object and attaches trailing preprocessing information to the last located
36 node (currently to the last statement) that has been visited in
37 the file (unparse flag: "after").
38 
39 Node that the preprocessingInfo objects are always attached to AST nodes.
40 By switching the USE_OLD_MECHANISM_OF_HANDLING_PREPROCESSING_INFO flag,
41 you only change the mechanism which the unparser is based on!
42 If USE_OLD_MECHANISM_OF_HANDLING_PREPROCESSING_INFO is set to 1, then
43 the unparser simply ignores the preprocessingInfo objects that have
44 been attached to the AST nodes.
45 
46 Problems with the handling of preprocessing information can be
47 found in the directory ROSE/TESTS/KnownBugs/AttachPreprocessingInfo.
