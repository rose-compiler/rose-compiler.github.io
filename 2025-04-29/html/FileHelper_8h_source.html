4 // UNDER NO CIRCUMSTANCES SHOULD BOOST_FILESYSTEM_VERSION BE SET!!!
5 //
6 // The boost::filesystem version is not dependent on which compiler we're using, but rather which version
7 // of boost is installed. Hard-coding a boost version number based on the compiler version has a couple of problems:
8 // 1. We don't know whether that filesystem version is available on a user's machine since ROSE supports multiple
9 // versions of boost (e.g., filesystem 3 is not available before boost 1.44)
10 // 2. It pollutes things for the user, who might not want the version we select here (e.g., most users of recent
11 // versions of boost will almost certainly want version 3, not the version 2 we select).
12 // Therefore, we should never select a filesystem version explicitly here, but rather be prepared to handle any version
13 // that is installed. If ROSE cannot support a particular version of boost::filesystem on a particular architecture with a
14 // particular file then that should be documented where we state which versions of boost are supported, and possibly
15 // checked during configuration. [Matzke 11/17/2014]:
